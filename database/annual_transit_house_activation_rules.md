# 年間・現行天体ハウス影響ルール

## 1. 目的

年間ページの「今年の流れ」で、現行天体の移動と個人のハウスへの影響を時系列に整理する。

このルールでは、次の3種類を混同しない。

1. 現行天体のハウス遷移
2. 現行天体同士の組み合わせ
3. 現行天体とネイタル天体・感受点の組み合わせ

## 2. 対象天体

年間の遷移表示は、月を除く以下の9天体を対象とする。

- 太陽
- 水星
- 金星
- 火星
- 木星
- 土星
- 天王星
- 海王星
- 冥王星

ASC・MCは天体ではないため、通常の現行天体一覧には含めない。ただし、ネイタル感受点への接触対象としては扱える。

## 3. ハウスの定義

### 3.1 ソーラーハウス

ネイタル太陽のサインを1ハウスとして、現行天体のサインを12ハウスへ割り当てる。既存の年間予報で使用している `_solar_house` と同じ計算を使う。

### 3.2 ネイタルハウス

出生時刻・出生地から算出したネイタルのハウスカスプに、現行天体の経度を割り当てる。既存のPlacidusハウス計算と一致させる。

### 3.3 ハウス境界

現行天体がハウス境界を越えた日を遷移日とする。逆行で前のハウスへ戻った場合も、別の遷移として記録する。

## 4. 個別ハウス遷移ルール

現行天体について、次の変化を時系列で検出する。

- サイン移動
- ソーラーハウス移動
- ネイタルハウス移動

同じ日・同じ天体で複数の変化が起きた場合は、1件にまとめ、変化内容を併記する。

例:

```text
太陽が牡羊座へ移動 / ソーラー8ハウスへ移動 / ネイタル1ハウスへ移動
```

## 5. 現行天体同士の組み合わせ

### 5.1 同じネイタルハウスでの合

現行天体Aと現行天体Bが合（0度）を形成し、同じネイタルハウスにいる場合、そのハウスのテーマを強調する組み合わせとする。

```text
現行天体A × 現行天体B × 0度 × 同じネイタルハウス
```

ただし、合だけでは個人ハウスへの強い影響とは判定しない。両天体が同じハウスにいることを必須条件とする。

### 5.2 同じハウスへの集中

現行天体が3天体以上、同じネイタルハウスまたはソーラーハウスに集中する場合、単独遷移とは別に「ハウス集中」として扱う。

同じ天体・同じ日付の単独イベントを重複加算しない。表示上は、集中イベントを1件にまとめる。

### 5.3 異なるハウスにいる現行天体同士

現行天体AとBがアスペクトを形成していても、異なるハウスにいる場合、片方のハウスへまとめて加算しない。

この場合は、次のどちらかとして扱う。

- それぞれのハウスを個別に表示
- 2つのハウスをつなぐ「ハウス間テーマ」として別ルール化

## 6. 現行天体×ネイタル天体・感受点

### 6.1 直接接触

現行天体がネイタル天体、ASC、MCへ接触した場合、接触されたネイタル天体が存在するハウスを強く関連するハウスとする。

### 6.2 天体の役割

外惑星は長期的な構造変化、個人天体は具体的な出来事や実感の引き金として扱う。

優先度の目安:

1. 現行外惑星 × ネイタル個人天体・ASC・MC
2. 現行外惑星 × 現行個人天体の同一ハウス内接触
3. 現行個人天体 × ネイタル天体
4. 現行天体の単独ハウス遷移

これは表示順・重要度の候補であり、数値スコアとして導入する場合は別途ルール化する。

## 7. アスペクト別の扱い

| 角度 | 基本的な扱い |
| ---: | --- |
| 0度 | 天体の作用を統合・増幅する。ただし同一ハウス条件を確認する |
| 60度 | 機会・連携。ハウスへの圧力は弱め |
| 90度 | 摩擦・課題。ハウスのテーマを強制的に動かしやすい |
| 120度 | 自然な流れ・支援。ハウスのテーマが進みやすい |
| 150度 | 調整・修正。ハウス間の不一致を調整する |
| 180度 | 対立・顕在化。関係するハウス軸を強く意識しやすい |

## 8. 判定の優先順位

同じ日に複数の条件が成立した場合は、次の順で整理する。

1. ネイタル天体・ASC・MCへの直接接触
2. 同一ネイタルハウス内の現行天体同士の合・ハード角
3. 同一ハウスへの3天体以上の集中
4. 単独のネイタルハウス遷移
5. 単独のソーラーハウス遷移
6. サイン移動

同一の原因を複数のカテゴリで二重表示・二重加算しない。

## 9. 拡張ルールCSV

組み合わせ判定は、遷移文のCSVとは別に次のルールCSVで管理する。

```text
database/M_Annual_House_Activation_Rules.csv
```

組み合わせ判定を追加する場合は、次の列を使用する。

```text
Rule_ID
Enabled
Scope
Transit_Planet_A
Transit_Planet_B
Natal_Target
Aspect_Angle
House_Type
Priority
Activation_Mode
Text_Key
Title
Text_Description
```

`Scope` の例:

- `TRANSIT_HOUSE`
- `TRANSIT_TO_TRANSIT`
- `TRANSIT_TO_NATAL`
- `HOUSE_CLUSTER`

`Activation_Mode` の例:

- `EMPHASIZE_HOUSE`
- `BRIDGE_HOUSES`
- `TRIGGER_NATAL_HOUSE`
- `LONG_TERM_BACKGROUND`

現在の初期ルールは、同一ハウスの現行天体合・スクエア・オポジション、3天体以上のネイタルハウス集中、外惑星からネイタル天体・ASC・MCへの合・スクエア・オポジションを対象とする。

## 10. 遷移マスターCSV

遷移文の入力元は、次の専用CSVとする。

```text
database/M_Annual_Transit_House_Transitions.csv
```

CSVは、月を除く9天体について、次の324行をあらかじめ用意する。

- サイン遷移: 9天体 × 12サイン = 108行
- ソーラーハウス遷移: 9天体 × 12ハウス = 108行
- ネイタルハウス遷移: 9天体 × 12ハウス = 108行

### 10.1 CSV列

| 列 | 内容 | APIによる計算 |
| --- | --- | --- |
| `Planet` | 現行天体 | なし |
| `Transition_Type` | 遷移種別 | なし |
| `Transition_Value` | サイン名またはハウス番号 | なし |
| `Sign_ID` | サイン遷移時のサイン | なし |
| `Solar_House` | ソーラーハウス遷移時のハウス番号 | なし |
| `Natal_House` | ネイタルハウス遷移時のハウス番号 | なし |
| `Title` | 画面表示用の短い見出し | なし |
| `Text_Description` | 画面表示用の解釈文 | なし |
| `Sort_Order` | CSV内の管理順 | なし |

`Transition_Type` は次の3種類に限定する。

```text
SIGN_INGRESS
SOLAR_HOUSE_INGRESS
NATAL_HOUSE_INGRESS
```

### 10.2 CSVの初期状態と未入力行

CSV作成時は、文章未入力の行を次のようにする。現在は全324行へ超簡潔な仮解釈文を入力済みで、後から個別の文章へ差し替えられる。

```text
Title = -
Text_Description = -
```

天体位置、遷移日、ソーラーハウス、ネイタルハウスはCSVへ入力しない。出生データと天体暦からAPIが算出する。

## 11. CSV入力ルール

1. `Planet` は対象9天体の英字IDを使用する。
2. `SIGN_INGRESS` の `Transition_Value` は `ARIES`〜`PISCES` の英字IDを使用する。
3. `SOLAR_HOUSE_INGRESS` と `NATAL_HOUSE_INGRESS` の `Transition_Value` は `1`〜`12`を使用する。
4. サイン名・ハウス番号を日本語表記へ変更しない。
5. 未入力の文章は空欄ではなく `-` にする。
6. APIが計算する日付やハウス番号をCSVへ手入力しない。
7. 同一の`Planet`・`Transition_Type`・`Transition_Value`の行を重複させない。
8. 文章を追加した後も、遷移種別とキー列は変更しない。

同じ日・同じ天体でサインとソーラーハウスが同時に変わる場合は、APIが1件にまとめる。ネイタルハウスも同日なら同じイベントへ併記する。

## 12. 追加・変更時の確認事項

ルールを追加または変更する場合は、次を必ず確認する。

1. 現行天体同士と現行天体×ネイタル天体を混同していない。
2. 同じハウスにいる条件を確認している。
3. サイン、ソーラーハウス、ネイタルハウスの定義が既存計算と一致している。
4. 逆行による再遷移を欠落させていない。
5. 同一イベントを二重加算していない。
6. 月間ピークのルールを年間遷移へ勝手に流用していない。
7. ルール追加後に代表ケース、境界日、逆行ケースをテストしている。

現時点では、個別天体のサイン・ソーラーハウス・ネイタルハウス遷移を実装済みとし、現行天体同士の組み合わせによる強調判定は拡張ルールとして予約する。
