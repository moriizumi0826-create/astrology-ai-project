# 3Dマップ用の毎時天体データ

`transit_hourly_2026.csv` は、UTCの2026年1月1日00:00〜12月31日23:00を1時間刻みで保存した8,760行です。出生情報は含みません。既存の鑑定用CSVは変更しません。

## 列

- `utc_datetime`: UTC日時。末尾の `Z` はUTCを表します。
- `{天体}_longitude`: 地心・トロピカル黄経（度、0以上360未満）。既存の `swe.calc_ut(..., swe.FLG_SPEED)` と同じ計算。
- `{天体}_speed`: 黄経方向の速度（度/日）。負なら逆行です。

天体はSUN、MOON、MERCURY、VENUS、MARS、JUPITER、SATURN、URANUS、NEPTUNE、PLUTO、NORTH_NODE（真交点）。SOUTH_NODEは真交点の180度反対として従来どおり求めます。ASC・MC・ハウスは場所に依存するため保存せず、選択日時と出生地の緯度経度で都度計算します。

## 読み込みと精度

API起動時に1回読み込んでメモリに保持します。UTC換算した日時が毎正時と一致するときだけ利用し、端数時刻、2026年外、ファイル欠損・破損時は従来計算へ戻します。丸め・補間はしません。任意日付の選択制限は追加しません。

JSONは生成元のSwiss Ephemerisバージョン、計算フラグ、単位、CSVのSHA-256です。起動時に完全な毎時連続性・数値・チェックサムを検証し、年初・年央・年末の11天体を実計算と照合します。天文暦ファイルの有無などによって計算エンジンが異なる環境ではCSVを使わず、警告ログを出して従来計算します。

`TRANSIT_EPHEMERIS_CACHE_ENABLED=0` で無効化できます（既定は有効）。CSV変更の反映にはAPI再起動が必要です。日別鑑定・年運・出生チャートの計算は変更していません。

## 生成・検証

プロジェクトルートから実行します。既存ファイルは上書きせず、新しい出力先で生成して比較してください。

```powershell
python scripts/generate_transit_ephemeris.py --output-dir output/ephemeris-check
python -m unittest backend.tests.test_transit_ephemeris -v
python scripts/benchmark_transit_ephemeris.py
```

生成は既存バックエンドと同じpyswissephを使用します。テストでは8,760時点×11天体の黄経・速度の一致、時差・年境界・10分刻みのフォールバック、角度・ハウスを含むチャート一致を確認します。

## 再生API

`POST /api/transit-charts` は既存の出生入力と `target_time`、`target_dates`（1〜366日分の日付配列）を受け、同じ順番で `{"charts": [...]}` を返します。各要素は既存の `/api/transit-chart` と同じ形式です。単日APIも維持します。

フロントは再生ボタンを押したときだけ不足分を一括要求します。約30日分は1リクエスト、366件超は分割。再生期間の決め方は変更しません。進捗は取得済み件数を表示し、1回の一括応答では取得完了時に残件数がまとめて進みます。旧APIで404/405の場合のみ、従来の4並列取得へ戻します。

## ローカル検証結果（2026-09-12）

- CSV: 3,887,025 bytes（約3.9 MB）。保持中のPythonデータ概算: 7,232,912 bytes。
- 初回CSV読み込み・検証: 約497 ms。起動時だけ実行。
- 2026年9月1〜30日の12:00 JST、30反復の中央値: 直接計算33.144 ms、キャッシュ利用1.616 ms。これはローカルCPU処理のみで、Renderの通信時間やブラウザ描画時間は含みません。
- 同条件で天体計算は330回から0回。ハウス計算は30回のまま。
- 新規バックエンドテスト13件に合格。全8,760時点の11天体を直接計算と照合。
- ブラウザでV2の再生前に一括要求がないこと、再生ボタンから今日±15日の不足分を1要求で取得することを確認。スマホ幅で読込表示と再生を確認。
- mainの日別マップでも一括取得後の再生を確認。
- main・V2ともフロントのテストとビルドに合格。V2の既存APIテスト2件（dailyStarVibeの存在、金星7ハウスの説明文）は変更前でも失敗することを別worktreeで確認。今回は変更していません。

公開環境への反映・実測および100ユーザー同時利用の負荷試験は未実施です。

## mainのホロスコープ再生修正

追加依頼により、ホロスコープ内マップが1日分しか再生候補を持たない既存不具合も修正しました。このマップのみ表示日から既存の再生設定日数分を作成し、選択日が変わってもその日から再生できます。日付選択にV2の今日±15日制限は付けません。日別・月間・年間マップの候補日の決め方は従来のままです。

PCの1ヶ月設定で不足分30日の一括取得が200応答し、再生停止ボタンに切り替わってマップの日時が進むことをブラウザで確認しました。
