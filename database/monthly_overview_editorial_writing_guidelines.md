# 月間総評CSV 執筆ガイド

対象CSV: `database/M_Monthly_Overview_Editorial.csv`

このファイルは共通仕様だけを定義する。実際の執筆作業では、対象年月の `monthly_overview_editorial_writing_guidelines_YYYY_MM.md` を必ず読み、このファイル単独では作業しない。

## 1. このCSVの役割

このCSVの1行は、特定の太陽星座期における、ソーラーハウスとネイタルハウスの組み合わせ専用の月間総評である。

- `Edition_ID`: 年と太陽星座期。例: `2026_CANCER`
- `Solar_House`: 太陽がその人のソーラーハウスのどこを通るか
- `Natal_House`: 同じ太陽星座期に、太陽が最も長く滞在するネイタルハウス
- 1 Edition_ID は `Solar_House 1-12 x Natal_House 1-12` の144行で構成する
- 表示時は、対象日の Edition_ID と計算済みの2ハウスで1行だけを取得する

日付の開始・終了や天体位置はCSVに保存しない。表示時に天体計算・トランジットカレンダーから決める。

## 2. 執筆時に見る情報

別メモや別ファイルは作らない。各144行を書く時は、その太陽星座期の現行天体一覧を直接確認する。

- 太陽星座期と、太陽が作るソーラーハウス上の主題
- 木星、土星、天王星、海王星、冥王星の長期配置
- 水星逆行など、期間の大部分を占める短中期要因
- 期間内の主要な星座移動・逆行開始・順行復帰
- 金星が入るソーラー／ネイタルハウスと、その期間内の星座移動

現行 x ネイタルの個別アスペクトと、現行天体同士の詳細アスペクトは、このCSVではまだ使わない。

## 3. 解釈の優先順位

本文は、次の順番で意味を組み立てる。

1. `Solar_House`: その期間に人生のどの領域が前に出るか
2. `Natal_House`: 実感、生活、行動としてどこに現れやすいか
3. 期間内の星座移動・逆行転換: 今期の流れがどこで変わるか
4. 過ごし方: 活性度と注意度を両方踏まえた現実的な力の使い方

太陽の主題を軸にする。ほかの現行天体を、全て列挙しない。本文に入れる背景は最大2つまでにする。

## 4. 個人用の長期背景は別枠にする

木星、土星、天王星、海王星、冥王星のネイタルハウスは、人ごとに異なり、太陽期の144行だけでは正確に固定できない。そのため、月間総評本文にはこれらのネイタルハウスを決め打ちで書かない。

表示時に鑑定対象年月の `database/M_Personal_Long_Term_Background_YYYY_MM.csv` を照合し、総評の下へ「あなたの長期背景」として別枠で出す。

CSVの使い分けは以下とする。

- `Record_Type=background`: `Primary_Planet + Primary_Sign + Target_Natal_House + 有効期間` で個人背景を取得する
- `Record_Type=resonance`: `Primary_Planet + Secondary_Planet + 両天体の星座 + Match_Type + 有効期間` で重なりを取得する
- `Active_Flag=1` の完成行だけを表示対象にする

- 個人背景: 現在の `Transit_Planet + Transit_Sign + Natal_House` が一致する行を取得する
- 表示は最大2件。土星・海王星・冥王星から負荷や再構築の要因を1件、木星から拡大や救いの要因を1件選ぶ
- 天王星は変化要因として、上位2件に入る場合だけ採用する
- ハウスを移る日には、計算結果に従って文章を正確に切り替える
- この別枠の文章を、144行の総評本文へ機械的に連結しない

さらに、トランスサタニアンと太陽・火星・木星、またはトランスサタニアン同士が重なる場合は、同CSVの `Record_Type=resonance` から最大1件を「今、強まっている重なり」として表示する。

- `same_sign`: 同じ星座にいる重なり。短期天体が長期テーマを点火する場合は最優先
- `same_natal_house`: 同じネイタルハウスにいる重なり。同じ生活領域へ複数のテーマが集まる場合に採用
- ソーラーハウスは星座から一意に決まるため、`same_sign` と重複する `same_solar_house` の別文章は作らない
- 外惑星同士だけの重なりは長期背景として扱い、短期的な出来事を断定しない

## 5. 期間内の変化の書き方

ソーラーハウスは「今期に何が前に出るか」だけでなく、期間の途中で何が切り替わるかも書く。

- 対象月だけでなく前月末10日間も確認し、対象月まで状態・星座滞在・影響が続く重要イベントを採用する
- とくに木星・土星の星座移動、逆行転換、太陽星座期の開始、当月の同座を成立させる移動は見落とさない
- `M_Transit_Calendar_<年>.csv` から、当該太陽星座期内の星座移動・逆行開始・順行復帰を確認する
- 本文には、主題を動かす変化を最大2件だけ採用する
- 金星が心身の軽さ、楽しみ、自分らしさ、人との関わりを回復させる位置へ入る場合は、上限とは別に必ず採用する
- 採用した変化は、`時期 + 天体 + 移動先の星座 + その人のソーラーハウス上の意味` を一続きで書く
- 日付が転機として重要な場合は「6月末」「7月中旬」のように時期を入れる。厳密な日付が鑑定の読みやすさを損なう場合は、日付だけを羅列しない
- 変化の前後で、何を整える時期から何を動かす時期へ移るのかを書く
- ネイタルハウスは、変化が本人の生活でどこに現れやすいかを大づかみに示す役割に留める。日ごとのネイタルハウス移動は本文へ入れない

太陽が次の星座へ移る日は次の Edition_ID の開始なので、現在のEdition本文では終盤の切り替わりとして必要な場合だけ触れる。

### 金星の扱い

金星は、重い配置の中で得られる喜び、安心、自分を心地よく扱う余裕を示す要因として毎回確認する。

- 金星がソーラー1・5・7・11ハウス、またはネイタル1・5・6ハウスに入る／滞在する場合は、本文に独立した一節を設ける
- とくにソーラー1ハウスでは、見た目、好み、日常の手入れ、自分を前向きに扱う感覚を回復要因として書く
- 全体に注意や負荷が多い Edition では、金星の小さな楽しみや軽さを「気休め」ではなく、実際に流れを支える要素として扱う

## 6. 列ごとの執筆基準

### Title

- 14-28文字を目安にする
- 今期の主題を一文で示す
- ハウス名や天体名をそのまま並べない
- 同じ Edition_ID 内で、異なる行が同じ題名にならないようにする

### Summary

- 90-150文字を目安にする
- 「何が中心か」と「どういう力の使い方が合うか」を一続きで書く
- 本文の冒頭を短縮しただけにしない

### Interpretation

- 500-900文字を目安にする
- 3-4段落で書く
- 第1段落: 今期の全体像
- 第2段落: Solar_House と Natal_House が重なる具体的な現れ方
- 第3段落: 期間内の星座移動・逆行転換が、今期の主題をどう変えるか
- 第4段落: 今期に合う過ごし方。無理に成果を急がない場合も、意味のある行動として書く
- 期間内に主題と結び付く星座移動・逆行転換がある場合は、第2段落または第3段落で1-2件を自然に織り込む
- 天体・サイン・ハウスの専門語は、本文では必要最小限にする

### Action

- 120-220文字を目安にする
- 2-3文で、今期に合う具体的な姿勢を書く
- 命令口調の箇条書きにはしない
- Interpretation の結論を、実生活の優先順位へ落とす

## 7. 文体と内容のルール

- 「必ず成功する」「病気になる」「破局する」「儲かる」と断定しない
- 不安を煽る表現にしない
- 気力低下を怠慢として扱わない
- 「運気」「エネルギー」「変化」だけで意味を済ませない。生活、仕事、対人、休息、判断など現実の現れ方を書く
- 個別アスペクトを使わない段階では、特定の出来事を予言しない
- 全144行で文章構造と語尾を機械的に繰り返さない
- `Solar_House` と `Natal_House` の役割を逆転させない
- 活性度と注意度が同居する版では、前進と休息の両方を矛盾なく書く

## 8. 144行の作業順

1. 当該太陽星座期の現行天体一覧を確認する
2. Solar_House ごとに12行をまとめて書く
3. 同じ Solar_House 内では、Natal_House 1-12 の実感差を明確にする
4. 12行書くごとに、題名・Summary・Interpretation の重複を確認する
5. 全144行を書いた後、各列の空欄、文字数、同一文を検証する

Solar_House が同じなら「人生領域の主題」は共通してよい。しかし、Natal_House が異なる12行では、生活上の実感・取り組み方・注意点を必ず変える。

## 9. 完成条件

各 Edition_ID について、以下を満たした時だけ完成とする。

- 144行がある
- `Solar_House` と `Natal_House` の全組み合わせが1回ずつある
- `Title`、`Summary`、`Interpretation`、`Action` に空欄がない
- `Interpretation` が500文字未満または900文字超過の行がない
- 同一 Edition_ID 内で Title が重複しない
- 同一 Edition_ID 内で、正規化後の Summary / Interpretation / Action が重複しない
- プレースホルダー、文字化け、未確定メモが残っていない
- 12行ずつ読み、Solar_House の主題と Natal_House の実感が正しく分かれていることを確認する
- 当該太陽星座期に主題と結び付く星座移動・逆行転換がある行は、時期と変化の意味が本文に入っている

## 10. 月別の個人用長期背景CSV

対象CSVは月ごとに分ける。

```text
database/M_Personal_Long_Term_Background_YYYY_MM.csv
```

例:

- 2026年7月: `M_Personal_Long_Term_Background_2026_07.csv`
- 2026年8月: `M_Personal_Long_Term_Background_2026_08.csv`

汎用の全星座組み合わせCSVは作らない。その月に実際に存在する星座配置・星座移動・逆行転換・重なりだけを生成し、その月の動きに合わせて文章を書く。

- `background`: 木星・土星・天王星・海王星・冥王星の当月配置 x ネイタル12ハウス
- `resonance`: 当月のトランスサタニアンと太陽・火星・木星、またはトランスサタニアン同士の重なり
- 当月に存在しない星座・組み合わせの行は作らない
- 未完成行は `Active_Flag=0` のままにし、表示しない

## 11. 月別長期CSVの列定義

| 列 | 用途 |
|---|---|
| `Record_ID` | 月・条件・有効期間を含む一意ID。変更しない。 |
| `Month_ID` | `YYYY-MM`。ファイル名の年月と一致させる。 |
| `Record_Type` | `background` または `resonance`。 |
| `Primary_Planet` | 背景天体、または重なりの主天体。 |
| `Secondary_Planet` | `background` は `ANY`。`resonance` は相手天体。 |
| `Primary_Sign` | 有効期間中の主天体の星座。 |
| `Secondary_Sign` | `background` は `ANY`。`resonance` は相手天体の星座。 |
| `Match_Type` | `planet_natal_house`、`same_sign`、`same_natal_house`。 |
| `Target_Natal_House` | `background` と `same_natal_house` は1-12。`same_sign` は `ANY`。 |
| `Valid_From` / `Valid_To` | その星座組み合わせが当月に成立する期間。 |
| `State_Changes` | 期間内の逆行開始・順行復帰など。なければ `none`。 |
| `Tone` | `activation`、`caution`、`mixed`。 |
| `Title` | 表示用の題名。 |
| `Interpretation` | 当月の動きを含む完成解釈文。 |
| `Priority` | 同時成立時の選択優先度。変更しない。 |
| `Active_Flag` | 完成・検証済みの行だけ `1`。 |

## 12. 月別CSVに作る行

`M_Transit_Calendar_<年>.csv` を使用し、その月の実配置から生成する。

- `background`: 木星・土星・天王星・海王星・冥王星について、当月に滞在する星座ごとにネイタル12ハウスを作る
- 月途中で星座を移る天体は、移動日前後で `Valid_From` / `Valid_To` を分ける
- 逆行開始・順行復帰は行を分割せず、`State_Changes` に日付と変化を記録する
- `same_sign`: 当月に2天体が実際に同じ星座にいる期間だけ作る
- `same_natal_house`: 当月の実際の星座組み合わせと有効期間ごとにネイタル12ハウスを作る
- `same_solar_house` は `same_sign` と重複するため作らない

対象となる12ペアは固定する。

- `URANUS`、`NEPTUNE`、`PLUTO` x `SUN`
- `URANUS`、`NEPTUNE`、`PLUTO` x `MARS`
- `URANUS`、`NEPTUNE`、`PLUTO` x `JUPITER`
- `URANUS` x `NEPTUNE`、`URANUS` x `PLUTO`、`NEPTUNE` x `PLUTO`

月ごとに星座移動数が異なるため、総行数は固定しない。生成スクリプトの出力件数をその月の正とする。

## 13. background行の執筆ルール

1行は、当月の `Primary_Planet + Primary_Sign + Target_Natal_House + State_Changes` の完成解釈である。

- `Title`: 12-28文字
- `Interpretation`: 220-420文字、3-5文
- 冒頭で、その長期配置が当月の本人に何を求めているかを書く
- ネイタルハウスに、どのような実感・負荷・余地として現れやすいかを書く
- `State_Changes` がある場合は、日付または上旬・中旬・下旬と、変化の前後を必ず書く
- `State_Changes=none` の場合も、「今月を通して続く背景」であることを自然に示す
- 月間総評の言い換えではなく、その配置だから追加で分かる具体的な意味を書く
- 木星は拡大・余地・楽しみ、土星は責任・境界・再構築、天王星は更新・自由度、海王星は感受性・曖昧さ・休息、冥王星は変容・集中・手放しを中心にする

## 14. resonance行の執筆ルール

### same_sign

- 当月に実際に同じ星座にいる期間だけ書く
- `Interpretation`: 220-420文字
- 共有する星座、開始・終了時期、2天体の働きがどう強まるかを書く
- 太陽・火星は当月の点火、木星は拡大・救い、外惑星同士は長期背景として扱う
- ネイタルハウスを決め打ちしない

### same_natal_house

- 当月の `Primary_Sign + Secondary_Sign + Target_Natal_House` を全て反映する
- `Interpretation`: 220-420文字
- 同じ生活領域へ2天体の異なる働きが集まる意味を書く
- 星座名を省略せず、当月の配置であることを明示する
- `same_sign` の文章をハウス名だけ差し替えて流用しない

## 15. 表示選択とPriority

- 個人背景は最大2件。土星・海王星・冥王星から負荷・再構築側を1件、木星から拡大・救い側を1件選ぶ
- 天王星はPriorityが上位2件に入る場合だけ採用する
- resonanceは最大1件
- 同じペアで両方成立する場合は `same_sign` を `same_natal_house` より優先する
- 太陽、火星、木星、外惑星同士の順に、既存Priorityで比較する
- 月間総評へ文章を機械連結せず、独立した「あなたの長期背景」として表示する

## 16. 月別CSVの作業手順

1. 対象年月のCSVを生成スクリプトで作る
2. 生成直後に行数・ID・有効期間・条件列を検証する
3. `background` は `Primary_Planet + Primary_Sign + Valid_From + Valid_To` の12行を1単位にする
4. `same_sign` は1有効期間を1単位にする
5. `same_natal_house` は天体ペア・星座組み合わせ・有効期間の12行を1単位にする
6. 1単位のTitle・Interpretation・Toneを埋める
7. 文字数・内容・重複を検証する
8. 検証済みの行だけ `Active_Flag=1` にする
9. 他月のCSV、条件列、Priorityには触れない

## 17. 月別CSVの完成条件

- ファイル名と全行の `Month_ID` が一致する
- 生成時の行数・Record_ID・条件列を維持している
- `Valid_From` / `Valid_To` が対象月内で、開始日が終了日を超えていない
- `Active_Flag=1` のTitleは12-28文字、Interpretationは220-420文字
- `State_Changes` がある完成行は、その時期と意味を本文に含む
- `same_sign` はネイタルハウスを決め打ちしない
- `same_natal_house` は両天体の当月星座と対象ハウスを反映する
- 正規化後のTitle・Interpretationに条件違いの丸写しがない
- 文字化け、プレースホルダー、改行によるCSV行ずれがない
- `Active_Flag=1` の行に空欄がない

作業完了時は、対象ファイルを指定して検証する。

```powershell
python scripts/validate_personal_long_term_background.py database/M_Personal_Long_Term_Background_2026_07.csv
```

検証が成功するまで `Active_Flag=1` の行を表示対象にしない。
