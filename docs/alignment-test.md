# 望みと資質の照らし合わせ：テスト版

独立ページ `frontend/alignment.html`。ログインなしで固定8問 → 出生情報 → 回答別の追加2問 → 仮まとめ → 項目別の反応・補足 → 更新履歴を利用する。

## 現在使える部分

- 既存 Swiss Ephemeris の出生図計算を `POST /api/alignment/chart` から呼ぶ。氏名不要、回答・自由記述は送らない。ファイル・DB・AIには保存しない。
- 10天体・Placidusハウス・伝統的支配星・アスペクト・オーブを返す。元の計算モジュールは変更しない。
- 出生時刻は必須。時刻不明のチェック・出生図なしでの継続は廃止し、APIでも時刻不明を拒否する。
- 出生地は47都道府県から選択。初期値は東京都。日本国内のお試し用に各都道府県庁所在地の代表座標とAsia/Tokyoを使用し、座標は入力させない。代表座標での概算であることを表示する。
- 座標データの参照元：https://data-okoku.ezic.info/view/japan-prefectural-capitals 。精密な出生地点の代替ではない。
- 計算失敗は表示して再試行する。計算成功前に追加質問やまとめへ進ませない。
- 追加質問は `POST /api/alignment/questions` が固定回答・補足から1〜3問生成する。出生図は質問生成に渡さず、回答を誘導しない。
- `POST /api/alignment/analysis` が回答・自由記述・計算済み出生図から見立てを返す。補足時も同じAPIで再解釈し、維持・修正・要確認と変更理由を表示する。元のまとめは直近20件、補足は最大50件。AIへ渡す補足は直近10件。
- 画面は質問・出生情報・結果・補足に絞る。テスト版の実装説明、保存・読込・ファイル操作メニュー、下部の長い説明は表示しない。回答と履歴はページを開いている間だけ保持する。既存のブラウザ保存データを自動読込・変更・削除しない。

## ローカル起動

結果画面は、望む稼ぎ方を上部に置き、「重なっているところ」「確かめたいところ」「次に試すこと」の3カードで整理する。段落の羅列を避け、箇条書き・番号付きの行動案・出生図の根拠枠を使い分ける。各カードの「この項目を補足・訂正する」で直下に入力欄を開き、対象項目を再選択させない。条件・訂正は本人の原文を添えてAIが再解釈し、変更理由を表示。キャンセルは見立てや履歴を変更しない。詳細と更新履歴は折りたたみ、結果画面では質問用のサイドバーや大きな導入を表示しない。

1. リポジトリルートで `python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8104 --no-access-log`
2. frontendで `npm run dev -- --host 127.0.0.1 --port 5185 --strictPort`
3. `http://127.0.0.1:5185/alignment.html`

Vite開発サーバーは `/api/alignment` を8104へプロキシする。既存の他画面のAPI先は変えない。配備ビルドでは既存の `VITE_API_BASE_URL` を使用。静的GitHub Pagesだけでは出生図のAPIは動かないため、このバックエンドも更新する必要がある。API未配備・接続不能のときは出生図の計算から先へ進めない。

## 金運AI専用の接続設定

- ローカル設定：リポジトリルートの `.env.money-ai`（Git対象外）。
- `MONEY_AI_API_KEY`：金運AI用に作成した専用キー。
- `MONEY_AI_MODEL`：専用のモデル設定。初期値 `gpt-6.1-sol`。GPT-6系ではreasoning effortをlowにし、推論トークンを含め出力上限を6000にする。
- 通常機能の `OPENAI_API_KEY` / `OPENAI_MODEL` へフォールバックしない。
- ローカルの専用ファイルはリクエストごとに読み直す。キーの入力・保存後はバックエンドの再起動不要。
- 配備環境では専用ファイルを置かず、同名の専用環境変数を設定する。
- OpenAI側でも金運AI用プロジェクト・キーに分けると、利用量を分けて管理できる。キーや設定ファイルを記事・スクリーンショット・Gitへ含めない。

## AIの入出力と根拠

OpenAI Responses APIの構造化出力を使用。キーはサーバー側だけで使用し、Responsesの保存は `store=False`。回答・自由記述と出生図の事実がAIへ送られる。氏名や出生日時の原文はAIの入力へ入れず、計算結果だけを渡す。サーバーで出生図を再計算し、ブラウザから送られた天体配置は受け取らない。

AIは解釈本文と実在する根拠IDを返す。存在しない根拠IDや本文内の天体配置・度数表記を検出したときは回答を採用しない。天体の位置・ハウス・アスペクト数値は計算した事実だけをUIに表示する。これは数値の捏造を抑える仕組みであり、解釈の意味の正しさまで保証するものではない。

匿名利用はプロセス内で1接続元につき12回/時、全体60回/時、同時3件に制限。SDKの自動再試行はしない。複数プロセスで公開運用する場合は共有カウンター等への移行が必要。入力長、質問数、出力長も制限する。エラー時は入力を維持し、固定文をAIの回答として代用しない。

2026-10-25、専用キーとgpt-6.1-solで実APIの質問生成・初回の見立て・補足後の再解釈をブラウザから確認済み。固定回答から3問を生成し、出生図の根拠を含む見立てを表示。対応範囲を事前設定するという補足に対し、境界の曖昧さを課題としない読みへ更新し、価値の手応え・需要の確認へ焦点が変わった。更新前の履歴も保持。既存機能のキーは流用しない。

公式の入出力仕様：https://developers.openai.com/api/docs/guides/structured-outputs
