## サーバーの利用資格確認

`AccessContext`は、将来の認証・契約アダプターが検証済みの情報だけを供給する内部型。HTTPパラメーター、任意ヘッダー、Cookieの自己申告、localStorageをそのままこの型へ変換しない。

| 状態 | 有料機能 | APIの扱い |
|---|---|---|
| 未ログイン | 不許可 | 有料APIは401 |
| ログイン済み・無料／期限切れ | 不許可 | 有料APIは403 |
| ログイン済み・有効な資格と将来の期限あり | 許可 | 本人の所有権も確認したうえで処理 |
| 契約確認中／取得失敗／期限情報不明 | 確認できるまで不許可 | 有料APIは503。契約なしとして上書き保存しない |

- `GET /api/v3/session`は状態・利用者ID・機能ルール・サーバー確認時刻・有効期限を返す。`Cache-Control: no-store`。
- `GET /api/v3/health`はV3ローカルAPIの識別用。個人データや秘密情報を返さない。
- 現時点の供給元は未ログインのみ。実認証やブラウザからの会員状態切り替えは未接続。
- 無料・有料・期限切れ・確認失敗の疑似状態は、自動テスト内の依存差し替えだけで検証する。HTTPから状態を偽装する入口は作らない。
- `require_paid_access`が有料API用の共通入口。まだ既存の鑑定APIには接続しない。V3 APIに既存の無認証ルートを丸ごとマウントしない。
- ブラウザの機能ルールは表示用であり、API呼び出しの許可証ではない。各有料APIで期限を再確認する。
- 有効期限はUTCの時差付き日時で扱い、期限と同時刻なら無効。買い切り等を採用する場合は別途永続資格を設計し、期限欠落を無期限有料と解釈しない。
