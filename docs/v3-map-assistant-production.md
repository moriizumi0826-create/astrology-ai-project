# V3 AIガイドの本番設定

- 自由入力：有効な有料会員・招待会員・所有者確認アカウントのみ。API側でも権限を検証する。
- 固定質問：全員利用可能。画面内の固定回答を返し、APIを呼ばない。会員が同じ質問をAPIへ直接送った場合もOpenAIを呼ばない。
- 固定文の共通データ：`frontend/v3/map-assistant-faq.json`。バックエンドも同じファイルを読むためデプロイに含める。

## Render本番APIの環境変数

| 名前 | 設定 |
| --- | --- |
| `OPENAI_API_KEY` | 本番用の秘密キー。Renderの環境変数にのみ保存し、コード・フロントには入れない |
| `V3_MAP_ASSISTANT_MODEL` | `gpt-6-luna`（省略時も同じ） |
| `V3_MAP_ASSISTANT_ENABLED` | `true`で自由入力を有効化。未設定・falseは停止 |
| `V3_MAP_ASSISTANT_DAILY_LIMIT` | 省略時20。会員1人・日本時間1日あたりの成功回答数 |

本番ではキー未設定時にデモ回答を返さず、利用不可を表示する。固定質問は停止中でも利用可能。
既存制限は会員ごとに10回/分・60回/時（APIプロセス単位）。入力500文字、履歴最大6件×600文字、出力最大750トークン。全体予算の上限ではない。

送信内容は質問・直近の履歴・マップ表示コンテキスト・本人と表示チャートの出生日時。氏名・メールアドレス・出生地そのものは自動送信しない。Responses APIの`store`はfalse。

## 自分のテストと通常利用の使用量分離（2026-10-04）

- 使用量分離のコードと関連自動テスト23件は実装・検証済み（OpenAIはモック、実課金なし）。有効化には下記の環境変数設定が必要。本番の配信状態はRenderで確認する。
- `V3_MAP_ASSISTANT_SPLIT_USAGE=true`の時、ローカル環境の自由質問と公開サイトの所有者アカウント（既存のサーバー側owner判定）は`OPENAI_TEST_API_KEY`、その他の有料・招待会員は従来の`OPENAI_API_KEY`を使う。
- 未設定／falseでは従来のキーを使う。キー登録前に公開サイトのAIを壊さないための段階導入設定。
- 分離有効時はテストキー未設定・通常キーと同一なら自由質問を503で停止。テストキーが無効・上限到達でも通常キーに切り替えない。固定質問は引き続きAPI未使用。
- 会員区分をブラウザから指定する機能は設けない。モデル・回答指示・日次回数制限・送信コンテキストは変更しない。キーや会員メールをAIの入力へ追加しない。

### 設定する順番

1. OpenAI Platformでテスト用の別プロジェクト（例：`Celestial Atelier Testing`）を作り、そのプロジェクトで秘密キーを作成する。既存プロジェクトとキーは通常利用用として残す。
2. Render本番APIの環境変数に`OPENAI_TEST_API_KEY`を追加し、`V3_MAP_ASSISTANT_SPLIT_USAGE=true`を設定する。既存の`OPENAI_API_KEY`は変更しない。
3. ローカルの`.env`にも同じテスト用キーと分離スイッチを設定し、バックエンドを再起動する。キーをチャット・Git・フロントへ入れない。
4. OpenAIのUsage（https://platform.openai.com/usage）でプロジェクトを切り替え、テストと通常利用の使用量／費用を確認する。分離前の過去の利用分は遡って分類されない。

別プロジェクトによる環境分離と秘密キーの環境変数管理：[OpenAI公式文書](https://developers.openai.com/api/docs/guides/production-best-practices)。コードではキーが別プロジェクトに属するかまでは確認できないため、作成時にプロジェクトを確認する。

## 1日20回の管理（詳細）

- 有料・招待・所有者確認アカウントすべて対象。日本時間0時更新。固定質問とローカルのデモ回答は消費しない。
- Supabaseに回数を保存し、ログインし直し・Render再起動でリセットしない。複数タブ・サーバーの同時要求もDBで直列化する。
- 送信前に1枠予約し、正常回答を確定した時点で使用済みにする。通信・生成失敗時は解放。予約は10分で期限切れ。生成済み回答を端末が受け取れなかった場合は消費済みになり得る。
- 残り回数は処理中の予約を差し引く。管理DBが確認できない場合は自由質問を停止し、無制限に送信しない。固定質問は継続可能。
- テーブルには会話・出生情報を保存せず、ユーザーID・予約ID・日付・成功状態・期限のみ保存する。過去30日より古い行はその会員の次回アクセス時に削除。
- ローカルのテスト認証だけメモリ管理。本番用SQLを適用したことにはならない。

## マップ情報

- 天体メニューの内側／外側／両方に応じて天体を選別し、送信する表示ラインの端点も補う。アスペクト最大24件、天体最大32件。
- 内側は出生図、外側は選択日時。実データのカスプを用いて「出生図基準のハウス」「選択日時基準のハウス」を明示。外側には出生太陽星座を1としたソーラーハウスも付与する。
- ソーラー基準は**表示チャート**の出生太陽。別人のチャートではアカウント本人の基準と混同しない。
- 表示用の仮カスプや推定天体を実測データとして渡さない。不明なハウスはnull。再生中は現在フレームの天体とカスプを使用。
- 全体傾向と個人への影響を区別し、場所に依存する外側ハウスを世界共通とは扱わない。追加のEphemeris/API呼び出し・AIツール実行は提供しない。

2. Renderで上記キーと有効化設定を登録する（キーの内容をチャットに貼らない）。
3. 固定質問の応答と無料会員のロックを確認する。実AIへの試験送信は従量課金が発生する。

停止時は`V3_MAP_ASSISTANT_ENABLED=false`に戻す。課金・招待設定は変更不要。
