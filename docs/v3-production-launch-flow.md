# V3 本番環境移行フロー

更新日：2026-09-27
対象：`C:\dev\astrology-v3` / `codex/v3-integration`

## 目的

公開プレビューで確認中のV3を、実際の会員登録・月額課金・有料機能提供ができる本番サービスへ移行するための手順を整理する。

本番の基本導線は次のとおり。

**LP・出生データ入力 → 無料版 → 会員登録／ログイン → Stripe Checkout → Webhookで契約確認 → 有料版を解放**

決済完了画面へ戻ったことだけでは有料化せず、Stripeの署名済みWebhookとサーバー保存済みの契約状態を根拠にする現在の構造を維持する。

## 現在地

本番Supabase、Renderの本番フロント・API、独自ドメイン、独自SMTP、Turnstile、法務ページ、Stripeライブ商品・Price・Portal・Webhookは構築済み。URLは一般告知しておらず、新規課金スイッチはOFF。2026-09-26に対象会員による月額400円の限定実決済を1件行い、有料解放と解約予約の導線を確認した。Better StackでサイトとAPIの外部死活監視を設定し、テスト通知メールの到着まで確認済み。現在は一般告知前の残項目を検証中。

| 項目 | 現在の状態 | 本番化で必要な対応 |
|---|---|---|
| V3フロント | 本番Static Siteと`thecelestialatelier.com`で稼働 | 実機スマホ・ログイン後の総合確認 |
| V3 API | 本番Web Serviceと`api.thecelestialatelier.com`で稼働。外部死活監視あり | 負荷・障害・依存先を含む監視の確認 |
| 認証 | 本番Supabase、独自SMTP、Turnstileを設定済み。ログイン・再設定を確認 | 新規登録から再訪まで本番実機で一連を確認 |
| 出生情報 | 本番DB・RLS・削除導線を設定済み。手動暗号化バックアップを取得し、別所保管も確認 | 隔離環境への復元はユーザー判断で保留。本番での保存・削除の未確認箇所を確認 |
| 決済 | Stripeライブ商品、JPY 400の月額Price、Portal、Webhookを接続済み。限定実決済1件を確認 | 新規課金は停止のまま維持。Webhook再送・障害時の運用確認 |
| 有料判定 | 限定実決済後の有料解放と解約予約を確認。新規課金スイッチはOFF | 期限終了・支払い失敗など未確認の状態と復旧手順を確認 |
| 共有テスト会員 | 公開プレビュー専用 | 本番に移行しない |
| main・V2 | 既存公開を維持 | V3公開確認後まで切り替えず、切り戻し先として残す |

公開プレビューでは、通常のSupabaseログイン、Stripeテスト決済、Webhook反映、有料ホロスコープ、契約管理画面まで確認済み。ログイン情報はGit管理外のローカルファイルに保存している。

## 本番移行の前提

### 本番・プレビューの環境分離を維持する

`production`と`preview`の境界、Stripeライブ／テストキーとPriceのモード検証、課金停止スイッチ、契約照合・復旧、退会・出生情報削除は実装済み。本番Renderには本番SupabaseとStripeライブ環境の値を設定し、プレビューの共有テスト会員・テスト決済とは分離している。限定実額決済後は新規課金スイッチをOFFに戻している。一般公開の判断までOFFを維持する。

### 7. 限定本番テストを行う

限定テストでは、`V3_BILLING_ENABLED=false`のまま先に本番APIへ`V3_BILLING_ALLOWED_USER_ID`（対象会員のSupabase UUID）を設定する。本番の`V3_BILLING_ACCESS_MODE`は未設定でも`single_user`が既定で、対象IDが空なら誰も申し込めない。次に全体停止スイッチを一時的に`true`へ変更し、決済前に対象会員だけ申込可能、別の無料会員は申込ボタンが無効・Checkout APIがHTTP 403になることを確認する。対象会員でもスイッチが`false`なら申込不可。契約管理画面はこの制限の対象外とする。対象IDをコードや公開フロントへ埋め込まない。

### 9. 公開後の監視と切り戻しを行う

#### 異常時の優先順位

1. `V3_BILLING_ENABLED=false`で新規Checkoutを停止する。
2. 課金導線にメンテナンス表示を出し、無料機能は可能な限り維持する。
3. Renderを直前の正常デプロイへロールバックする。
4. Stripe Webhookの失敗イベントを確認し、修正後に再送する。
5. StripeとSupabaseの契約状態を照合し、有料資格を復旧する。
6. 二重課金や誤課金が疑われる場合は、新規課金を止めて個別確認する。

フロントだけを旧版へ戻しても、すでに開始したサブスクリプションは自動停止しない。既存契約の継続・解約・返金はStripe側の状態を別途確認する。
